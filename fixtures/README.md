# Project-owned LX source fixtures

All JavaScript here is original fixture code dedicated to the public domain
under CC0 1.0 (SPDX: `CC0-1.0`). No third-party music source or credentials are
included. The audio catalog is generated by this application's Rust backend.

These files follow the official LX source contract: header metadata, a Promise
request handler registered with `lx.on`, and `lx.send(EVENT_NAMES.inited)` with
`sources.local`, `type: "music"`, `actions: ["musicUrl"]`, and `qualitys: []`.
Sources resolve playback URLs; searching the catalog is the player's job.

| File | Expected result |
| --- | --- |
| `legal-local-source.js` | Initialize, request the player's `/catalog.json`, and resolve a matching synthesized tone URL. |
| `legal-http-utils-source.js` | Validate original tone legacy fields, exercise buffer/MD5/AES-128-CBC/zlib, POST JSON to `/resolve`, and return the real synthesized tone URL. |
| `legal-direct-source.js` | Initialize and resolve the supplied loopback URL without requesting the catalog. |
| `broken-source.js` | Import rejects the JavaScript syntax error without executing the script. |
| `wrong-url-source.js` | Initialize; playback resolution rejects the forbidden `file:` URL. |
| `init-throw-source.js` | Static metadata import succeeds; enable reports the intentional initialization error. |
| `no-handler-source.js` | Enabling rejects a declared action without its request handler. |

The legal sources verify that `musicUrl` carries `source: "local"`,
`info.type: null`, and flattened legacy `musicInfo` fields:
`name`, `singer`, `source`, `songmid`, `interval`, `albumName`, `img`, `typeUrl`,
`albumId`, `types`, `_types`, `filePath`, and `ext`.
For local tracks, `albumId` is empty and `types` is an empty array.

The network fixture uses the callback form
`lx.request(url, options, (error, response, body) => ...)` and checks the returned
cancellation function. It requires HTTP 200 and a parsed JSON array of catalog
records `{id, title, url, artist?, duration?}`. The request target is derived from
the supplied `http://127.0.0.1:<port>/<audio-file>` URL, and matching is by
`record.id === musicInfo.songmid` (`tone-1`, `tone-2`, or `tone-3`). The resolved URL
must use that same loopback base. Importing any fixture only saves its metadata
and source code; the player separately asks for trust before execution.

The POST + Utils fixture is limited to `tone-1`, `tone-2`, and `tone-3`.
It uses `buffer.from`, `buffer.bufToString`, `crypto.md5`, and
`crypto.aesEncrypt(data, "aes-128-cbc", key, iv)`. The fixed 16-byte key and IV
are original public test bytes, not credentials. It awaits RFC 1950
`zlib.deflate` and `zlib.inflate` and verifies that decompression restores the ID.
The request is `POST http://127.0.0.1:<port>/resolve` with
`Content-Type: application/json; charset=utf-8`, `X-Fixture: lx-http-utils-v1`,
and `{id, checksum, cipher, compressed}`. The backend enforces a single
`Content-Length`, reads the complete body within two seconds, limits it to
2 KiB, verifies `checksum === lowercase MD5(id)`, validates both payloads as
nonempty base64, and returns `{id, url}` only for a generated demo tone.
It deliberately does not decrypt or inflate client-provided payloads; the
fixture verifies its own compression round-trip. This exercises utility
transport and the request callback, not a cryptographic authorization scheme.
The GET fixture remains available for local imports and baseline comparisons.

Run `node fixtures/verify-fixtures.cjs` from the project directory to verify the
six original GET/direct/error fixtures against a minimal LX API mock. This checks their Promise and
callback behavior, complete local legacy fields, catalog shape, loopback-only
URLs, and intentional error cases. It complements the Rust runtime tests; it
does not claim to validate Boa or real audio playback.
The POST + Utils fixture requires the implemented LX utility bridges and the
real project loopback server; its full runtime path is covered by Rust/worker
acceptance checks instead of that deliberately small Node mock.
