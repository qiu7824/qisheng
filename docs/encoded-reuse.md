# 持久编码音频复用

编码块与媒体许可分别管理。`CacheIdentity.media_context_sha256` 绑定实际 `ResolvedMediaKey`；稳定数据键另含精确 URL 摘要、原曲、实际平台/质量、源 SHA/策略、块大小及格式版本。流序号、源会话和批准 epoch 保留在当前视图中，不作为持久许可保存。

## 验证和读取

每个远程播放地址仍经过新的精确 URL 批准。批准之前没有媒体 GET、表示绑定或解码。批准后，已有持久块以 `Range: bytes=0-0` 和旧强 ETag 的 `If-Range` 验证；206 只能返回完整的一个字节，强 ETag、总长度和 identity 编码必须一致。

忽略 Range 的 200 仅在完整区间均已验证、响应强 ETag 和 Content-Length 一致时复用。客户端读取一个最多 8192 字节的 DATA 帧，再使用受保护的完整缓存视图；`range_supported` 保持 false，`cache_random_access` 表示缓存自身提供随机读取。活动完整视图不因其他流的空间压力丢失区间，释放其 lease 后恢复正常淘汰。

URL、解析上下文、源策略、实际质量、ETag 或长度变化均失配。弱标签和无标签响应不能建立持久表示；稀疏缓存只能在实际 Range 能力下补洞。重定向不会扩展批准地址，401/403/404/410/429 等真实 HTTP 拒绝不能播放旧缓存。显式分段读取的 HTTP 错误直接保留状态并交给后端，不混入网络异常的立即重试。

单次完整 200 响应在当前流中全部下载后，只有所有区间均已验证、仍在实际配额内并由活跃 lease 保护时，缓存才提供当前流的反向读取和尾部定位。该能力不依赖远端 Range，也不建立弱标签或无标签的持久复用许可；弱标签或无标签的下一次批准仍下载完整当前正文。逐出的区间或不完整正文不能启用缓存随机访问。

已知总长、强 ETag 和实际配额允许时，Range 读取最多预取当前游标之后两个区间，显式读取优先于预取。seek、取消和表示 epoch 变化中断旧请求；未知总长、弱标签和 200 响应不扩展 Range 预取。预取的 408、5xx 或临时网络失败延后至显式读取再次取得真实结果；401、403、404、410、429 等拒绝立即保留 HTTP 状态，解码器即使暂停或 PCM 队列已满也终止供给，旧缓存和已排队 PCM 不再呈现。

预加载保持累计 2 MiB HTTP DATA 和现有 PCM 限额。提升为前景之后，已经验证的块可以登记持久索引；该登记不增加媒体请求或扩大投机预算。

## 索引、完整性和回收

v2 登记保存数据键、强 ETag、总长、块大小、区间、完整正文 SHA256 及 ledger epoch。所有索引扫描、正文校验、双槽持久提交、冷认领和回收由缓存 I/O 拥有者执行。临时 v1 登记继续按原冷恢复规则回收。

冷读取先验证目录和 ownership header，再验证完整正文 SHA。Windows 读取句柄允许共享读，拒绝写和删除；正文替换失配时保留原文件、记录 foreign 占用，不能仅凭旧 header 删除替换内容。新块的持久处理结束后才开放 `read/contains`，避免最后一个块提前可读后取消导致索引撤回。

多个播放视图共享不可变块。磁盘和编码字节按唯一物理块计量，视图、pin、读者 hazard 和完整视图保护各自保留归属；真实 unlink 与 durable deregistration 完成前不释放物理占用。clear 同时推进 RAM epoch 和持久 ledger fence，旧候选、准备、发布或登记不能恢复已清理索引。候选失配的清理使用完整 metadata CAS，不删除后来登记的新表示。

每次双槽增长、初始化 header 和整批 clear 维护都预先核对实际配额；空间不足如实失败，不通过提前扣减占用报告清理成功。可选持久登记拒绝不阻止正常临时播放，真实 I/O 失败仍保留在缓存状态中。

验证使用真实 HTTP、Memory PCM、冷子进程、正文替换、双读取视图、受保护句柄、配额压力和索引损坏工况。硬件发声、设备切换和全部文件系统故障单独验收。
