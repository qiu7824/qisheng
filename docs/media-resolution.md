# 音乐匹配与 URL 信息缓存

接口位于 `backend`、`platforms::matching`、`domain::media` 和 `repository`。兼容基线为 LX Music Desktop v2.12.6 提交 `ad95d5091c9ed689fa72b5e5c849df65f5a679ce`，数据库使用 schema 6。

## 元数据匹配

`find_music_matches` 使用 `list_id/music_id` 读取列表独立记录。`music_matches` 查询相同列表记录的持久结果；缓存身份包含原曲 ID、平台、完整记录的规范化 SHA256 和算法版本。列表编辑期间完成的旧结果以取消或冲突终止，不覆盖新记录。

每个其他原生平台搜索第一页、25 条记录，最多检查 100 条。四个共享并发名额控制实际搜索线程；父任务等待全部线程退出，取消与截止时间贯穿原生 HTTP 请求。KG 分组展开只检查前 25 条，并记录截断数；其他平台异常分页数量返回结构化错误。响应及结果 JSON 的累计上限为 8 MiB。

匹配保留上游三个选择阶段和九级排序，每个平台选择一个真实候选。标题、艺术家和专辑按明确规则归一化；已知时长差最多 5000 ms，未知时长有独立理由。Live、Remix、伴奏、翻唱及其他版本词的签名必须一致，空艺术家及仅含子串的错误艺术家不匹配。候选保留实际平台 ID、hash、质量和扩展字段；音乐 URL 始终由已批准的自定义源解析。

完整搜索结果默认保留 7 天，最长 30 天。部分平台失败的结果记录 `searched_platforms/failed_platforms`，保留 30 秒；显式查找会重新执行部分结果。缓存写入不修改列表、曲目、用户 revision 或 outbox。

## 解析与批准

自动切源由 `set_auto_switch_source` 控制，默认关闭并保存到播放检查点。启用后，原曲解析失败可按排序尝试真实候选，每个候选平台最多尝试一次。元数据搜索覆盖原生平台，再按当前源的 `musicUrl` 能力及候选质量筛选。常规请求在每个实际候选上重新协商首选质量；显式 `play_list_track.quality` 保持严格质量约束。

列表和当前逻辑曲目保留原始记录。`resolved_track` 投影实际替代候选，`approved_audio_identity` 保存实际平台和质量。解析调用使用实际候选的完整旧版 `musicInfo`，不使用同名曲目拼造平台映射。

URL 信息缓存以原曲身份、实际质量、自定义源 SHA256、批准策略版本和解析 DTO 摘要为键。替代候选使用原始 DTO 与实际候选 DTO 的组合摘要，并完整保存实际候选记录。默认 TTL 为 15 分钟，最长 24 小时；时间回拨、过期、源权限变化及实际 HTTP 拒绝会使条目失效。原曲或候选元数据变化生成不同键。原生 TTL 是额外的有限缓存策略；固定上游 URL 仓没有 TTL 字段。

缓存命中仍检查自定义源批准，只生成新的待批准 URL。`approve_playback_url` 再次核对当前列表 DTO、选择源、SHA256、策略和源会话 epoch，随后生成新的批准身份；批准前没有媒体 GET。URL 缓存不保存、恢复或授予媒体下载权限。已注册 Catalog 资产只有在地址精确相等并取得实际资产 authority 时沿用资产许可。

前景与预加载解析共用一个 JavaScript 会话。取消保持该会话的闭包，清理当前操作的 HTTP、timer 和 Promise 工作；源切换及关闭终止进程。解析流程包含初始化后的剩余时间，共享 70 秒截止时间。写入缓存前再次核对播放 generation、源 epoch、原始元数据和预加载操作；旧结果不能重建清理后的缓存。

## 失败与控制

`PlaybackSnapshot.failure` 保留阶段、原生媒体错误、真实 HTTP 状态和请求 URL 的 SHA256。网络、协议、超时、存储、解码与输出错误分别处理，原错误字符串继续可用。预加载失败保留同样的媒体细节，不修改当前播放的失败状态。

真实传输 401、403、404 或 410 且请求摘要与当前批准一致时，使 URL 信息失效，并对同一实际曲目最多强制重新解析两次；每个新地址仍等待精确批准。源脚本明确返回“服务器繁忙”时使用结构化 `RateLimited`，延迟 2 秒和 4 秒，最多三次请求，不触发换源。其他文案中的数字不会被解释为 HTTP 状态。

`refresh_playback_url` 强制绕过缓存，保留实际候选及实际质量。`clear_media_cache` 清空两个信息缓存表，使在途解析及预加载结果失效；`clear_audio_cache` 管理编码音频块。`media_cache_stats` 返回信息表的行数及字节数。每表最多 4096 行、8 MiB，按持久访问顺序淘汰，事务失败保持原数据。

持久图片缓存和跨播放编码音频复用仍属于 M05 后续工作；设备、DSP、下载、备份、同步及外部控制按完整后端计划实施。
