# 原生备份恢复

原生 JSON 与 gzip 备份通过独立后端恢复，使用 `lx_native_backup` version 1 格式。SQLite 数据仓为 schema 15。

## 命令与查询

`preview_native_backup` 接收绝对 `path` 和 `replace_tracks`，后台读取选中文件并生成预览。默认保留已有曲目，`replace_tracks=true` 使用替换策略。预览返回操作 ID、输入摘要、数据仓版本、各章节数量和需要重新激活的资源。

`commit_native_backup` 接收 `preview_operation_id` 和 `input_digest`。提交校验完整预览、实际曲目绑定及数据仓版本；输入被修改或期间发生用户数据变更时，必须重新预览。

`native_backup_preview` 查询当前预览；`native_backup_import_result` 按操作 ID 查询提交回执和偏好应用状态；`native_backup_archive` 查询保留的安全归档章节。

## 持久化与恢复

列表、不喜欢规则、已知曲目的编辑歌词和导入回执在同一 SQLite 事务中提交。列表与不喜欢规则的同步记录属于同一个数据仓版本。未知曲目的编辑歌词保留在归档中，回执区分已应用和待关联的数量。

偏好与未批准的音源写入 `player-state.json`，操作 ID 和摘要与设置保存在同一个文件封套中。文件写入失败时，已提交的 SQLite 回执保留待恢复状态；重启在启动后台服务前完成剩余步骤。已应用的操作不会覆盖后来修改的设置，相同操作 ID 配不同摘要会报冲突。

提交前检查完整设置封套的 8 MiB 上限。回执和归档合计最多 16 MiB，最多保留 64 个操作；待应用的回执不会被淘汰。当前播放曲目的编辑歌词在数据库提交后刷新，保持播放 generation。

## 资源激活

现有音源的精确脚本、批准状态、选择项和本地文件授权保持完整。新音源按脚本 SHA 去重，作为未批准脚本导入，需要显式批准后才能执行。

声明的本地路径作为未验证数据归档，需要重新选择文件。下载章节保存禁用的计划，禁止携带目标目录授权，不创建可运行的下载任务。扩展字段和未知曲目的歌词保留为数据。

SQLite 物理快照的安装和整份 profile 恢复仍需连续持锁的停机、关库、安装、启动与回滚链路；单份 SQLite 文件不包含 `player-state.json` 的全部内容。

## 验证范围

原生恢复的 6 项实际后端测试、11 项 SQLite 数据仓测试和 3 项设置文件测试通过。验证包含同播放 generation 的 HTTP 歌词刷新、实际文件写入失败后的重启恢复、保留现有批准与文件权限、输入及版本冲突、完整设置大小预检、事务回滚、归档篡改和回执计数溢出。物理快照安装与系统设备验收另行执行。
