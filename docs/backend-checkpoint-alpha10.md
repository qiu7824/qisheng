# LX Native 0.3.0-alpha.10 后端检查点

日期：2026-10-08。Windows x64/MSVC，Rust/Cargo 1.99.0，SQLite schema 7，后端协议1。兼容基线为 LX Music Desktop v2.12.6 提交 `ad95d5091c9ed689fa72b5e5c849df65f5a679ce`。

## 可运行范围

实际播放链支持0.5–2倍速度、默认保调及0.5–1.5倍独立移调。保调采用固定存储WSOLA，非保调采用预制抗混叠sinc表，工作在现有解码线程；独立移调采用4096点FFT、128帧hop的频谱峰区域移动，工作在Device/Memory共用输出链的均衡器之后、音量和静音之前。初始单位倍率保持直接样本路径，FFT计划、scratch及固定缓冲在回调外准备。

原始媒体位置按每帧不可变标签确认，采样率转换和移调保留同一标签区间；FFT启动补零、预取、断流与暂停不推进内容时钟，静音正常推进。暂停或设备隔离保留已经取出的未输出帧，seek以新epoch废弃旧内容。解码与移调均执行有限EOF排空，最后有效标签输出后才结束。设备格式交接先完成配额预约与计划准备，失败保留旧端点和未输出内容。

目标设置持久化并以CLI、查询、快照和事件暴露；保存回执、请求序号与真实渲染确认分别表示。前台和预加载使用同一处理设置通道，已有PCM保留自身生成设置；单纯倍率变化保持媒体generation、地址许可、缓存epoch与预加载身份。Memory以锚定20ms批次调度，实际DSP耗时与调度超期计量在回调之外。

频谱bin取整、窗口湿声增益约0.96和启用后的4096帧延迟均具有明确数值边界；返回单位移调保留延迟干声直至媒体或seek重置，避免跳过未播放内容。参数、公式、延迟单位与接口见[播放处理接口](playback-processing.md)。
