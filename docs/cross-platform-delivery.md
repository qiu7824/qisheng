# 栖声桌面端私有仓库与三平台交付设计

## 仓库

仓库名称：`qiu7824/qisheng`。可见性：Private。默认分支：`main`。项目包含桌面客户端源码、锁定依赖、必要测试夹具、图标、许可证及原生构建工作流。

上传采用明确文件清单。用户曲库、歌单数据库、账号设置、音源密钥、历史安装包、编译缓存、操作日志、临时脚本、安卓产物及本机 Cargo 路径配置不进入仓库。源码包与文件清单分别记录 SHA-256；上传前重新校验，发生变化的文件必须重新检查。

## 构建矩阵

| 平台 | 架构 | GitHub 执行环境 | 产物 |
| --- | --- | --- | --- |
| Windows | x64 | windows-2025 | ZIP，包含栖声.exe、CLI 与 MSVC 运行库 |
| macOS | Apple Silicon arm64 | macos-15 | APP、ZIP、DMG |
| macOS | Intel x64 | macos-15-intel | APP、ZIP、DMG |
| Linux | x64 | ubuntu-24.04 | tar.gz，包含程序、图标与 desktop 文件 |

macOS 首轮最低版本设为 15.0，Linux 首轮验证基线为 Ubuntu 24.04。更低版本或其他发行版需增加对应环境验证后纳入支持范围。两个 macOS 架构独立原生构建，不通过跨架构模拟结果代替验证。

工作流仅手动启动，可选择单个平台或全部平台，同时最多运行两个任务，每项任务最多运行 120 分钟。固定 Rust 1.99.0 与 Cargo.lock，第三方 Actions 固定到已核对的提交。工作流权限为 `contents: read`，检出不保留凭据，不自动创建公开 Release。

## 验证与打包门槛

1. 核对 Rust 实际 host 与目标架构一致。
2. 检查源代码格式与全部测试目标的原生编译。
3. 串行执行单元测试和集成测试，任何失败均阻止打包。
4. 在独立资料目录启动原生窗口，保存截图并检查退出状态；Linux 使用 X11 虚拟显示服务与独立 D-Bus 会话。
5. 重新构建不含 smoke 功能的生产程序。
6. 从打包目录启动 CLI，实际打开独立数据库并读取状态。
7. 记录目标架构、源码提交、工作流编号、验证范围和文件 SHA-256。

自动化音频验收使用内存输出，验证解码和播放状态；扬声器输出、设备热插拔、系统媒体键、文件选择器、托盘与窗口关闭行为仍必须经过目标系统交互验收。原生窗口截图、自动化测试通过与实机音频通过分别记录。

## 平台适配工作项

| 范围 | 验收内容 |
| --- | --- |
| 数据目录 | Windows 保持 LOCALAPPDATA/LXNative；macOS 使用 Library/Application Support/LXNative；Linux 遵循绝对 XDG_DATA_HOME 或 HOME/.local/share |
| 便携模式 | 数据存放于可执行文件旁；macOS APP 的资料目录放在 APP 外部，避免修改应用包 |
| 原生文件身份 | 资料目录锁定、本地曲库授权、符号链接限制、文件身份变化与撤销授权 |
| 目录监听 | macOS 目录变更通知、Linux inotify、停止监听与重新扫描 |
| 备份恢复 | 导入、导出、重启后恢复、异常中断、文件替换与并发冲突 |
| 系统集成 | 托盘、单实例、媒体会话、文件打开、通知和快捷键 |
| 播放器 | 本地播放、切歌、逐字歌词、歌单持久化、封面、在线请求和音源工作进程 |

涉及资料完整性的未实现路径应返回明确错误；不得取消文件身份检查、用成功空实现代替原生操作，或跳过失败测试来满足交付门槛。

## 包格式与签名

Windows 包包含程序所需的 MSVC 运行库。Linux tar.gz 面向上述验证基线，需要系统提供 ALSA、Cairo/Pango 和相应桌面组件；它不声明为独立于发行版的 AppImage。desktop 文件供安装到用户应用目录时使用，便携运行直接启动包内 `qisheng`。

macOS 构建生成应用包并做 ad-hoc 签名及签名验证。Developer ID 签名和 Apple 公证属于后续正式发行门槛，需要专用签名身份与账号配置；ad-hoc 签名不声明为已公证发行版。

## 缓存与保留

构建输出、测试资料、日志、截图和打包中间目录均放在执行机临时目录。依赖下载缓存按目标架构和 Cargo.lock 区分；不上传大型 target 缓存。每次任务使用单个 target 路径，阶段之间复用，不执行全量清理。

安装包与验证记录分开上传为私有 Actions artifacts，保留 7 天。验证成功后将正式交付包保存到项目交付目录。任何计费设置和付费额度均保持账号原有配置，不由工作流调整。

## 验收记录

每个平台分别记录编译、测试、原生窗口、打包程序启动、实机音频与系统集成结果；有待验证项的平台不标记为可交付。必须完成四个构建目标以及三种操作系统的功能验收后，才能标记三平台交付完成。
