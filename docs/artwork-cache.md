# 图片解析和缓存接口

图片信息及编码字节保存在 `artwork_info/artwork_blobs`。缓存不修改原曲、用户列表、revision 或 outbox。图像界面消费以下后端接口。

| 接口 | 行为 |
| --- | --- |
| `resolve_picture` | 按 `list_id/music_id` 解析当前列表副本，返回异步回执及操作终态 |
| `approve_picture_url` | 按 `operation_id/url` 批准当前上下文的精确图片地址 |
| `cancel_picture` | 取消指定解析或获取操作，旧结果不落库 |
| `clear_image_cache` | 清理两张图片缓存表、验证过的 RAM 字节和在途操作 epoch |
| `picture_info` | 查询当前列表记录对应的信息，不获取网络图片 |
| `picture_operations` | 分页查询当前操作及最近终态，最多 100 条一页 |
| `picture_cache_info` | 分页查询缓存信息 |
| `picture_cached_bytes` | 返回已完整验证的编码字节页，每页最多 65536 字节 |
| `image_cache_stats` | 返回信息/字节的逻辑占用及带观察时间的共享数据库物理统计 |

## 路由和授权

原曲及实际候选的完整 DTO 摘要、路由版本和来源限定信息键。元数据 `picUrl` 与内置平台 `Picture` 提供器优先使用真实记录；已验证的实际播放候选只在当前原曲摘要仍匹配时使用。本地读取限定在 Catalog 已授权资产，使用资产身份、大小、mtime 和指纹的 permission stamp，不扫描相邻目录。

local `pic` 共用当前唯一 SourceWorker 会话，以实际 Catalog 文件桥 DTO 调用；源 SHA、策略和会话 epoch 参与完成与批准检查。源失效时可以沿用已授权本地嵌入图，不能虚构网络图片。后台工作与前景解析共享有界源调度，不创建另一个 JavaScript 会话。

远程信息命中只进入 `awaiting_approval`，不发图片 GET。音频 URL 批准不授予图片访问权；图片批准再次核对当前列表、真实候选、源权限、cache epoch 和精确地址。已验证持久 blob 可离线重新读取、校验和完整解码后进入 `ready`，不请求网络。

## 验证、配额和生命周期

网络响应使用固定 8192 字节 DATA 帧和有界 header；不跟随重定向、不解压、不使用系统代理或自动凭证。每张编码图片最多 8 MiB。PNG、JPEG、GIF 和 WebP 必须完整解码，声明 MIME 必须对应真实格式或明确的二进制类型；拒绝 HTML、SVG、其他格式、截断、错误 checksum、尾帧损坏及像素膨胀。

图片最大边长 4096，单帧最多 16 Mi 像素，动画最多 64 帧，累计最多 32 Mi 像素。解码器应用 64 MiB 分配限额，帧逐个验证后释放，编码 proof 保留 SHA、格式、尺寸、帧数和长度。取消检查贯穿解析、chunk、checksum、帧间以及最终发布。

图片信息表最多 4096 行、8 MiB；编码 blob 表按 SHA 去重，最多 1024 项、64 MiB，LRU 淘汰不截断内容。编码字节 query 只读取已经验证的有界 RAM LRU；RAM 未命中时先执行 `resolve_picture`，由工作线程离线验证持久字节。共享 SQLite、WAL 和 SHM 的真实文件统计与逻辑 blob 配额分列，不将逻辑 64 MiB 表述为物理磁盘上限。

图片服务按需启动四个预先预约、持续归属的工作线程，排队最多 16 项且请求元数据总量最多 4 MiB。元数据/源排队/本地后备共用 30 秒期限；等待用户批准后重新开始图片获取期限。关闭取消工作，等待实际 join，超时保留归属供继续等待。网络、文件标签读取和解码不在后端控制线程执行；当前 SQL 提交沿用事务仓串行模型，其全部磁盘延迟属于独立性能验收。

## 桌面显示缓存

ZSUI 桌面层采用按字节计费的最近访问淘汰策略，本地嵌入封面与网络封面共用 12 MiB 母图缓存；缩放、圆角和模糊背景共用 8 MiB 帧缓存；系统媒体 PNG 缓存为 512 KiB，应用标识帧缓存为 256 KiB。所有缓存均设条目数量上限。缩放帧不超过母图像素尺寸，由绘制器完成最终显示尺寸缩放。

正在显示的图片通过当前可见布局持有。缓存淘汰仅释放缓存自身的引用，活动图片仍可通过弱引用索引复用；滚出可见范围或关闭页面后释放对应活动引用。视图重建只接续活动图片，不复制整个缓存。上述 20.75 MiB 是缓存持有资源的预算，不是进程总内存上限；活动画面、解码临时分配、后端编码缓存及操作系统资源单独占用内存。

发现页、歌单墙、搜索歌单、专辑墙、榜单导航及侧栏只在条目进入可见范围时请求封面。网络封面下载最多并发 2 项，等待队列最多 16 项，排队超过 3 秒的旧请求释放状态并允许当前可见条目重新请求。桌面解码串行执行，最大尺寸 4096×4096，解码输出最多 64 MiB，并应用解码器分配限制；裁剪视图借用原像素，不再复制完整裁剪大图。

策略参照：[Qt QPixmapCache](https://doc.qt.io/qt-6/qpixmapcache.html)、[Flutter ImageCache](https://api.flutter.dev/flutter/painting/ImageCache-class.html)、[Flutter 解码尺寸参数](https://api.flutter.dev/flutter/widgets/Image/Image.network.html)。解码器不支持缩小解码时，仍需先解码原图，再缩小保留；缓存预算不替代解码阶段的尺寸和分配限制。
